# 玩家反馈：剧情承接与立绘一致性修复设计

日期：2026-08-04

## 目标

本批次修复当前 3.9.2 RC 中已经静态确认、能够直接对应玩家“上文不接下文、贴图混乱、文笔逻辑性不够”评价的问题：

1. 角色身份与屏幕立绘不一致，或角色离场后立绘仍残留。
2. 第三章“愿意谈联姻”过早成为不可逆婚约，第四章又没有退出机会，导致艾琳娜选项无提示消失。
3. 四个主结局先到十年后、随后又回到五年后；铁腕结局没有消费实际会战伤亡状态。
4. 人民领主结局遗漏正式妻子，并出现无来源的公爵头衔、低财富却全国最富庶、主角死后继续行动和地方治理突然变成全国革命等承接断点。

本批次采用“契约式修复”：先用回归测试锁定每个上游选择或状态必须被下游消费，再做最小范围的剧情、立绘和状态调整。不会对全篇文案做启发式替换。

## 方案比较

### 方案 A：只改表面文字

把“十年后”改成“五年后”、把“公爵”改成“领主”，并替换几张立绘。改动最小，但联姻仍会在“愿意谈”时锁线，人民结局仍不读取家庭状态，下一次扩写很容易再次穿帮。

### 方案 B：修复状态契约与对应文本（采用）

新增“联姻仍在商谈”状态，只有第四章明确接受婚约后才设置正式婚姻；让结局读取会战、财富、设施和伴侣状态；修正已确认的立绘身份与离场清场；以测试锁定这些关系。改动集中在既有场景，不重构九结局入口。

### 方案 C：合并核心结局与扩展尾声

把 `chapter5.rpy` 和 `endings_expansion.rpy` 的重复结局彻底整合为单一时间线。长期结构最好，但会大范围移动标签、调用和旧存档落点，不适合作为 3.9.2 的玩家反馈修复。

## 一、立绘身份与离场清场

### 两派代表

- 王后方代表使用现有 `queen_envoy_img`。
- 男爵方代表继续使用 `noble_werner_img`。
- 两人交替发言时显式切换立绘，不让一张脸连续代表双方。
- 同步保持 `Character.image`、`CHAR_IMG_TAGS`、`images_def.rpy` 和实际 `show` 一致。

### 小女孩

小女孩在城墙下向高处喊话，采用有名牌、无人物立绘的表现。删除成年铁匠妻子的错误立绘绑定和该段 `show blacksmith_wife_img`。这个空间关系本来就适合让孩子留在画面外，因此不以新增儿童立绘作为修复前置条件。

### 南境配角

- 公会税吏改用现有 `tax_collector_img`。
- 公会老账房改用现有 `merchant_guild_img`。
- 角色定义和所有对应 `show` 一并改动。

### 离场残留

- 男爵密使被送走后立即清场，再进入第三名信使的叙述。
- 艾琳娜离开艾登堡后立即清场，再叙述雷恩和暗百合的后续。

## 二、联姻从“商谈”到“正式接受”

新增普通存档变量 `marriage_proposal_open = False`，语义为“希尔达的提议仍在商谈”。

第三章：

- “回信，愿意谈这桩联姻”只设置 `marriage_proposal_open = True`。
- 不再提前设置 `marriage_route = True`。
- 决策记录改成“同意会面商谈联姻”，与玩家看到的选项一致。

第四章：

- 当 `marriage_proposal_open or marriage_route` 时进入英格丽会面。保留 `marriage_route` 是为了让停在会面前的旧存档也能获得重新确认机会。
- 菜单提供三类结果：接受纯政治婚约、接受并愿意经营关系、结束商谈。
- 前两项才设置 `marriage_route = True`，分别设置 `marriage_warm = False/True`；结束商谈设置两者为假。
- 三项都关闭 `marriage_proposal_open`。
- 玩家结束商谈后，第四章艾琳娜确认关系选项按原条件正常出现；玩家正式接受婚约后，艾琳娜段落明确提到已有婚约，不再只显示一个无缘由的“保持距离”。

兼容策略：

- 新变量加入 `characters.rpy` 默认值与 `save_compat.rpy` 的缺省字段。
- 已经过第四章的旧存档不回滚现有婚姻结果。
- 停在第三章之后、第四章会面之前且旧 `marriage_route=True` 的存档，会在原会面处得到三项确认；不会自动拆除玩家已读到的婚礼。

## 三、结局时间与铁腕伤亡

### 时间锚

- 四个核心结局的“十年后”统一为“战后第五年”，与扩展尾声的王历二十七年相符。
- 人民核心结局不再先跳到“几百年后”再返回五年尾声；结尾改成不制造新年份的后世评价。
- 角色归宿段落保留其战后数月／一年信息，但标题明确标为回看战后旧事，避免读者把它误认为五年尾声之后的新时间点。
- 不在本批次移动或重命名结局 label，以免扩大旧存档风险。

### 铁腕伤亡

扩展尾声的纪念碑读取 `iron_battle_outcome`：

- `pyrrhic` 延续正文的“两百多人阵亡”。
- `decisive` 延续正文的“七十多人阵亡”。
- 删除无来源的固定“三百七十二人”。

## 四、人民领主结局的因果与家庭

### 资源和治理结果

- 不再无条件宣称艾登堡是全国最富有的领地，也不再无条件宣称学校、道路和物资全部建成。
- 财富高低、`built_school`、`built_granary` 等既有状态只影响相应可见成果。
- 所有状态都保留一个成立的最低结果：战争没有吞掉艾登堡，领民仍愿意留下并参与治理。低财富路线可以和平，但必须呈现紧日子和未完成的工程。

### 家庭与伴侣

核心结局和扩展尾声都按互斥关系读取：

1. `elena_romance`
2. `marriage_route`，并继续区分 `marriage_warm`
3. `corsair_romance`
4. 无伴侣

英格丽使用现有立绘、城堡／花园背景和当前结局配乐。温暖婚姻写共同生活与共同治理；纯政治婚姻写各守职责但家庭状态明确存在。赛琳仍通过南境来信或物件进入尾声，不把她瞬移到内陆城堡。

### 身份、尺度与死亡

- 人民路线没有受封公爵，所有“公爵大人”改为符合当前身份的称呼。
- 艾登堡只作为一个被其他地方观察和借鉴的例子；全国改革来自之后许多人的谈判、反抗、失败和再尝试，不由主角一句话直接完成。
- 明确保留改革的阻力、反复和未完成状态，维持希望，但不写成无代价的全国乌托邦。
- 主角去世后停止使用第二人称让其继续行动；后世段落改用史家、继任者和其他人物作为行动主体。

## 五、测试与扫描

先写失败回归并确认红灯，再改正文：

1. 立绘语义测试：双方代表不能共用 tag；小女孩不能绑定成年女性；税吏和账房必须使用现有专用／语义相符立绘；两处离场必须先清场。
2. 联姻状态测试：第三章只开启商谈；第四章必须有接受、温暖接受、结束商谈三类结果；只有接受才设置 `marriage_route`；新变量必须进入旧档缺省初始化。
3. 时间线测试：四个核心结局不得再进入十年后；人民核心结局不得在扩展五年尾声前进入几百年后；角色归宿必须明确为回看。
4. 结局消费测试：铁腕扩展必须读取 `iron_battle_outcome`；人民扩展必须读取婚姻、财富和设施状态；主角死亡之后不得再出现第二人称行动句。
5. 修复 `scan_missing_portraits.py` 中错误的单词边界字符，并用测试证明未注册的 `show *_img` 能被闸门捕获。

完成后运行：

- `python -m unittest discover -s Tools -p "test_*.py" -v`
- 相关 Ren'Py testsuite 与完整 lint。
- `python scan_missing_portraits.py`
- `python scan_narration_overlap.py`
- 改动文件的 `show ... at left` 前置清场检查。
- `python Tools/scan_ai_smell.py`
- `python Tools/scan_canon.py`
- `python Tools/test_release_regressions.py`
- `git diff --check`

不依据全项目 59 条启发式候选做批量替换；本批次只修有上下文证据和回归断言的场景。

## 六、资源结论

- 美术：不需要新增。复用 `queen_envoy.png`、`noble_werner.png`、`tax_collector.png`、`merchant_guild.png`、`ingrid.png` 及既有背景。儿童专属立绘是可选增强，但城墙上下的空间关系采用画外喊话更自然，因此本批次不新增。
- 配乐：不需要新增。没有新场景类型，继续使用各结局和现有章节的音乐。
- 音效：不需要新增。改动没有新增必须靠声音表达的动作节点。
- 动画：不需要新增。只涉及现有立绘切换和清场。
- 包体：不新增任何二进制资源，预计包体不增加。

## 完成标准

- 玩家选择“愿意谈”不会在第三章静默锁死艾琳娜路线；第四章由玩家明确决定是否订婚。
- 已确认的五类身份错图与两处离场残留消失。
- 四个主结局不再十年→五年倒退，铁腕伤亡与实际战果一致。
- 人民结局能交代英格丽／其他伴侣，低财富文本成立，主角死亡后不再继续行动，全国变化有过程和阻力。
- 新旧存档字段安全，既有结局入口和持久化结局键不变。
- 所有规定门禁有本轮新鲜通过证据，工作树按主题小步提交。
